# BAAM (BG) 프로젝트 진행 발표

> 발표 준비용 자료. 최신 코드·문서(GDD, PvE-Mode-Design, Card-Data-Spec, git 이력) 기준으로 작성.
> 작성일: 2026-09-04 (2026-09-02 초안 갱신)

---

## 1. 프로젝트 개요

- **게임명:** BAAM (코드/리포 접두사 `BG`)
- **한 줄 정리:** 보드게임 《뱅!》 기반 **TRPG 스타일 마피아 카드 게임**
- **컨셉:** 《뱅!》의 역할 은닉·손패 전투 구조 + 《포 더 킹》의 확률 판정·성장 감각을 결합한 PC 턴제 카드 게임
- **엔진/구조:** Unreal Engine 5.8, GAS(Gameplay Ability System), **리슨서버** 멀티플레이(Steam)
- **모드:** PvP(4~7인, 기본) / PvE(싱글, 슬레이 더 스파이어식 진행)

### 핵심 플레이 감각

1. **역할 추리** — 숨겨진 역할과 승리 조건을 바탕으로 서로의 의도를 추리
2. **제한된 행동 선택** — 턴당 카드 사용 한도(기본 2장) 안에서 우선순위를 정함
3. **확률 감수** — 모든 갈색 카드가 대실패·실패·성공·대성공 4단계로 갈림
4. **빌드 구성** — 캐릭터·장비가 사용 한도·성공률·대성공률에 영향
5. **정보 추리** — 전원이 하나의 덱을 공유 → 남은 카드를 세어 상대 행동을 예측

## 2. 프로젝트가 푸는 문제 / 목표

원작 《뱅!》은 **대면 플레이 전용** 설계다. PC·온라인 환경으로 옮기면서 아래 네 가지를 다시 설계하는 것이 이 프로젝트의 목표다.

| 원작의 문제 | BAAM 의 해법 |
|---|---|
| 피해자가 응답 카드를 내야 진행되는 대기 구조 | **응답 필요 카드 비활성화** — 사용 즉시 서버가 결과를 확정 |
| 카드 수트로 판정(대면 전용 절차) | **수트 제거, 4단계 확률 판정으로 통합** (대실패/실패/성공/대성공) |
| 좌석 거리·사거리 계산 | **거리 개념 제거** — 모든 대상을 거리 없이 지정, 대신 빌드·대상 선택에 집중 |
| 정적인 "카드를 내려놓는" 연출 | **시네마틱 카메라 + 포스트 프로세싱**으로 공격/피격 연출을 확대 — 이 프로젝트의 차별점 |

세 가지 핵심 기술 축:

- **GAS** — 카드 효과(GA), 장비 지속 효과(Infinite GE), 확률 보정(AttributeSet)을 전부 GAS 위에서 표현
- **멀티플레이(Steam)** — 판정은 전부 **서버 권위**, 클라이언트는 예상 확률만 표시
- **시네마틱 연출** — 같은 규칙 위에 연출을 얹어 턴제 보드게임의 정적인 인상을 바꾸는 것이 목표

## 3. 최근 업데이트 (직전 발표안 대비)

| 구분 | 내용 |
|---|---|
| 카드 데이터 정합성 | `AbilityByCardId` 매핑 누락 수정, `DT_BGCard` PvE 덱 매수 필드 복구 — 두 곳 다 "고쳤는데 카드가 죽는다" 류 어긋남을 잡은 안정화 수정 |
| 카드 분류 | UI 뷰모델에 **장비 / 공격(대상 지정) / 마법(자신에게 사용)** 대분류(`EBGCardCategory`) 추가·반영 완료 |
| PvE 진행 | 진영별 덱 분리 뼈대 + 덱 구성 데이터 연결(`BuildPvEDeck`) + 뽑기/버리기 진영 라우팅 + AI 턴 재진입 버그 수정 |
| PvE 조우 루프 | 조우 승리 보상(장비 카드 지급), 조우별 좌석 스케일링, 부관 오폭 방지, 보상 손패 즉시 지급까지 연결 |
| 카드 UI | 카드 이미지 에셋 반영(위협·함정·마녀 등 개별 아트), 호버 시 확대·포커스 연출, `WBP_BGInfoTooltip` 신설 |
| 카드 프레임 머테리얼 | 외곽선 계산을 `MF_BGCardOutline` 함수로 리팩터, `M_BGCardFrame`/`M_BGCardDissolve` 그래프 정리(불필요한 노드 다수 제거) |
| 메인 메뉴 · HUD | `WBP_BGMainMenu`, `WBP_BGHUD`, 턴 패널·역할 아이콘 텍스처 수정, CommonUI 플러그인 활성화 |
| 아트 | 임시 모델 캐릭터 일부를 정식 모델링(수도사·마법사 등)으로 교체 시작 — 전체 교체는 아직 아님 |

## 4. 구현된 핵심 시스템

### 카드 판정 파이프라인
- 카드 사용 → 서버가 4단계 판정(대실패/실패/성공/대성공)을 **1회** 굴림 → `Resolution.*` 태그로 전달
- 결과 태그로 `AbilityByCardId` 에서 GA 선택 → `UGA_BGCardEffects` 가 `DT_BGCard` 의 `OutcomeEffects` 실행
- 판정 결과는 **서버 권위** — 클라이언트는 예상 확률만 미리 보여준다
- 검증 명령 한 벌로 데이터·태그·BP 매핑을 한 번에 확인 (`BG.ExpectedDeckSize 64`, `BG_DumpDeck`)

### 카드 데이터
- **총 64장 / 11종** — 갈색(공격·마법) 카드 + 파란(장비) 카드 3종(드워프 장갑·마녀의 부적 등)
- 장비는 판정 없이 장착 경로로 즉시 처리, 나머지는 4단계 확률 판정
- UI 뷰모델(`FBGCardView`)에 **장비 / 공격 / 마법** 대분류를 추가해 카드 표시·분류 로직을 한 곳(`BGCardViewLibrary`)으로 통일

### GAS 기반 전투 시스템
- `UGA_BGCardEffects`(정식 실행 경로), `GE_BGDamage` / `GE_BGHeal` / `GE_BGEquip`, `UBGAttributeSet`
- 어트리뷰트: 카드 사용 한도, 성공률/대성공률 보정, 방어(피해 무효화 확률) 보정 등 — 장비·직업이 이 축에 값을 넣는 구조

### 턴 · 로비 · 좌석
- `BGSeatComponent` — 입장 순 배치, 판 시작 시 랜덤 재배정
- `BGReadyComponent` / `BGMatchStartComponent` — 준비 상태·매치 시작 흐름, PvE 하한 인원·봇 스폰 분기 포함
- 턴 진행·카드 사용 한도(기본 2장)는 서버 권위로 관리

### 네트워크 · 세션
- Steam 온라인 서브시스템 기반 세션/방 코드 (`Session/BGOssPolicy`, `BGSessionFlow`)
- 손패는 `COND_OwnerOnly` 로 복제 — 남의 패가 보이지 않음
- 덱 셔플용 시드와 판정용 시드를 분리해 재현성 확보

### UI
- **View/Widget 계층 분리** — 뷰모델(`UI/View`, 로직 비의존)과 UMG 위젯(`UI/Widget`)을 명확히 갈라 의존 방향을 강제
- 카드 위젯: 드래그 앤 드롭, 확률 표시(기본/최종), 카드별 아트, 호버 확대·포커스 연출, 정보 툴팁
- 카드 프레임 아웃라인 글로우·디졸브 머테리얼 — 원형(archetype)별 값 정리, 그래프 리팩터 완료
- 좌석 보드/상세 위젯, 턴 패널, 판정 결과 알림 위젯, 메인 메뉴, HUD
- 월드 타겟팅 컴포넌트 + 하이라이트로 대상 지정 UX 지원

### PvE — 진영별 덱과 조우 루프까지 연결됨
- 같은 게임 로직을 재활용 — 새 게임을 만들지 않는 것이 설계 전제
- `BGAIBrainComponent` / `BGAIPlayerController` — 봇 AI 두뇌, 역할 고정 배정(플레이어=보안관, 봇=무법자), 좌석 채우기
- **진영별 덱 분리**가 뼈대 단계를 지나 데이터 연결(`BuildPvEDeck`)과 뽑기/버리기 라우팅까지 이어짐
- **조우 승리 → 보상(장비 카드 지급) → 다음 조우로 좌석 재스케일링** 흐름이 동작
- 밸런스 실측(런 길이, 적 강화 배분)은 남은 단계

## 5. 로드맵 대비 진행 상태

### 전체 우선순위 (GDD §12)

| 단계 | 내용 | 상태 |
|---|---|---|
| **P0** 핵심 규칙 프로토타입 | 역할·손패·턴, 4단계 확률 판정, 사거리/수트/수동응답 비활성화 | ✅ 구현 |
| **P1** 장비·캐릭터 빌드 | 자동 판정 장비, 확률 보정 어트리뷰트, 확률 미리보기 UI | ✅ 대부분 구현 |
| **P2** 디지털 전용 확장 | GAS 신규 카드, 재판정/조건부 발동, 장기 빌드 | 🔶 진행 중 |
| **P3** PvE 모드 | AI 행동 패턴, 전용 덱, 레벨 진행 | 🔶 아래 세부 단계 참고 |

### PvE 세부 단계 (PvE-Mode-Design.md §E9)

| 단계 | 내용 | 상태 |
|---|---|---|
| E-0 | 봇 PC 스폰 — 좌석 채우기 | ✅ 완료 |
| E-1 | PvE 전용 역할·직업 고정 배정 | ✅ 완료 |
| E-2 | AI 브레인 — 밧줄 스킵 + 최소 대기 | ✅ 완료 |
| E-3 | 진영별 덱 + 진영별 초기 손패 | 🔶 데이터 연결·라우팅 완료, 실측 검증 남음 |
| E-4 | 조우 리셋 경로 + 보상 → 다음 조우 | 🔶 보상 지급·좌석 스케일링 연결, 3조우 연속 진행 검증 남음 |
| E-5 | 적 장비·직업 배분·성격 | ⬜ 미착수 |

## 6. 남은 과제

- **Legacy GA 9종은 의도적으로 비활성** — 정식 실행 경로는 `UGA_BGCardEffects` + `DT_BGCard.OutcomeEffects` 하나뿐 (호출 경로만 끊고 코드는 보존)
- PvE 밸런스 실측 — 런 길이, 실패 시 처리, 중간 저장 등은 아직 미결정 (E10)
- 적 장비·직업 배분(E-5) 착수 필요 — 난이도 곡선의 마지막 축
- 장비·직업 보정 축(공격/회복/드로우 보정)은 설계상 확정이나 아직 어트리뷰트 미구현
- 캐릭터 모델링 전체 교체 — 현재 일부(수도사·마법사 등)만 임시 모델에서 정식 모델로 전환됨
- 시네마틱 연출 확대 — 카드 프레임 글로우/디졸브 리팩터는 완료, 전투 연출 확장은 지속 작업
