## 레이어 구조

```
┌─────────────────────────────────────────────┐
│  Layer 3 · PostProcess          "해석"       │
│  이미 만들어진 빛을 어떻게 읽을 것인가        │
│  → 빛을 만들지 않는다                        │
├─────────────────────────────────────────────┤
│  Layer 2 · SkyLight             "가독성"     │
│  그늘을 채운다 · 전방위                       │
│  → 형태를 만들지 못한다                       │
├─────────────────────────────────────────────┤
│  Layer 1 · Directional Light    "형태"       │
│  방향 · 그림자 · 입체감                       │
│  → 그늘을 채우지 못한다                       │
└─────────────────────────────────────────────┘
        + PointLight (모닥불) = 국소 액센트
```

**아래에서 위로 쌓는다.** 순서를 뒤집으면 반드시 두 번 일한다.
Layer 1 이 비어 있는데 Layer 3 을 만지면, Layer 1 을 고치는 순간 Layer 3 값이 전부 무효가 된다.

## Layer 1 · Directional Light — 형태를 만든다

### 담당

**빛의 방향.** 그리고 방향의 결과물인 **그림자.**
로우폴리에서 형태는 곧 실루엣이고, 실루엣을 만드는 것은 면마다 갈리는 명암이다. 그 명암을 만드는 유일한 레이어다.

### 못 하는 것

**그늘을 채우지 못한다.** 방향성 광원이라 빛이 닿는 면만 밝힌다.
"캐릭터가 어둡다" 고 여기를 올리면 → 밝은 면만 더 밝아지고 대비가 벌어져서 **어두운 면은 오히려 더 어두워 보인다.** 그리고 노을 느낌이 죽는다.

### 오늘의 사건 — 그림자가 하나도 안 나왔다

`Cast Shadows` 도 켜져 있는데 지면에 그림자가 전혀 없었다. 두 값을 같이 놓고 계산해보니 답이 나왔다.

```
그림자 길이 = 물체 높이 / tan(태양 고도)

Pitch −10°  →  높이 × 5.67
여관 높이 900  →  그림자 5100

Dynamic Shadow Distance = 3000
5100 > 3000  →  통째로 잘림
```

**"노을이라 각도를 낮춘다"** 와 **"씬이 작으니 그림자 거리를 줄인다"** 가 정면충돌하고 있었다.
둘 다 개별적으로는 맞는 판단인데 같이 쓸 수 없었다.

→ Pitch 를 −20° 로 올려 그림자 길이를 높이 × 2.75 로 줄이고, 거리를 10000 으로 늘려 해결.
**−18° ~ −22° 가 노을 느낌을 유지하면서 그림자가 실제로 렌더링되는 실용 구간.**

### 오늘의 사건 2 — 순수 역광

태양이 씬 뒤 지평선에 있어서 카메라를 향한 **모든 면이 그늘**이었다.
이 상태에서는 Layer 2 를 아무리 올려도 캐릭터가 계속 어둡다. 애초에 키가 안 닿기 때문이다.

→ **Yaw 를 120~140° 돌려** 태양을 측후방으로 옮기니 캐릭터 옆면에 따뜻한 키가 들어와 옷 색이 읽히기 시작했다.
오늘 적용한 것 중 **효과가 가장 컸다.** 촬영에서 해를 정면으로 두고 찍지 않는 것과 같은 이유다.

### 값

| 항목 | 값 | 왜 |
|---|---|---|
| `Use Temperature` / `Temperature` | ✅ / **2700K** | Hex 보다 물리적으로 일관됨. 시간대 프리셋 만들 때 숫자만 바꾸면 됨 |
| `Intensity` | **8 lux** | 노을은 약하다. 세지면 모닥불이 존재감을 잃음 |
| `Pitch` | **−20°** | 위 계산 |
| `Yaw` | 순수 역광 회피 | |
| `Source Angle` | **0.2** | 0 이면 그림자 경계가 지글거림. 로우폴리는 칼같은 경계가 생명 |
| `Dynamic Shadow Distance` | **10000** | 씬 크기 × 태양 각도로 결정 |
| `Contact Shadow Length` | **0.08** | 오브젝트 접지감 |

## Layer 2 · SkyLight — 가독성을 만든다

### 담당

**그늘을 채운다.** 전방위 광원이라 Layer 1 의 빛이 닿지 않는 모든 면에 들어간다.
그리고 앰비언트의 **색**을 정한다 — 그림자 영역이 검정이 될지 쿨톤이 될지는 여기서 결정된다.

### 못 하는 것

**형태를 만들지 못한다.** 사방에서 균일하게 오므로 그림자가 안 생긴다.
여기만 올리면 화면이 밝아지긴 하는데 **평평해진다.** 오늘 실제로 그 상태를 한 번 겪었다.

### 오늘의 사건 1 — 씬이 완전히 새까맣게 나왔다

지면은 밝은데 오브젝트만 순수 검정이었다. 앰비언트 기여가 **0** 이었다.
뷰포트 빨간 에러가 원인을 그대로 말해주고 있었다.

> *"A sky light with real-time capture enable is in the scene. It requires at least a SkyAtmosphere component, a VolumetricCloud component or a..."*

**Real Time Capture 는 아무 하늘이나 잡아주지 않는다.** 셋 중 하나가 필요하다:

1. `SkyAtmosphere` 컴포넌트
2. `VolumetricCloud` 컴포넌트
3. 머티리얼에 **`Is Sky`** 가 체크된 스카이돔 메시

스타일 때문에 1·2를 지웠고, 엔진 기본 `BP_Sky_Sphere` 의 머티리얼은 UE4 시절 것이라 `Is Sky` 가 없다.
**셋 다 해당이 안 되어 캡처 대상이 0개**였다.

→ Real Time Capture 를 끄고 `SLS Captured Scene` + 수동 `Recapture` 로 전환.

### 오늘의 사건 2 — 캐릭터가 검은 실루엣이었다

배경은 잘 나왔는데 캐릭터 7명이 검은 덩어리였다. 카드게임에서 누가 누군지 구분이 안 됐다.
값을 만지기 전에 **씬 구조에서 원인을 역산**한 게 빨랐다.

```
ABGCampfire::GetSeatTransform 이 캐릭터를 모닥불 쪽으로 향하게 배치
  → 모닥불은 캐릭터의 앞면만 비춘다
  → 카메라는 원 바깥에서 등을 본다
  → 등을 비출 광원이 SkyLight 밖에 없다
```

즉 이 게임에서 **캐릭터 가독성을 실제로 책임지는 것은 모닥불이 아니라 Layer 2** 였다.
시네마틱 카메라가 원탁을 선회하므로, 어느 각도에서도 작동하는 전방위 광원이 유일하게 안정적인 해법이기도 했다.

→ `Intensity Scale` 을 0.8 → **3.5** 로 과감하게 올림.

### 놓치기 쉬운 두 가지

- **`Lower Hemisphere Is Black` 이 기본 체크다.** 안 풀면 `Lower Hemisphere Color` 가 통째로 무시되고 캐릭터 하반신이 계속 까맣게 남는다.
- **`Sky Distance Threshold`** 는 "이 거리보다 먼 것만 하늘로 친다" 는 값이다. 기본 150000 이라 스카이 스피어가 그 안쪽이면 하늘로 인식되지 않는다. 캡처가 안 되면 여기부터 의심.

### 값

| 항목 | 값 | 왜 |
|---|---|---|
| `Source Type` | SLS Captured Scene | `Is Sky` 머티리얼 만들면 Real Time Capture 로 복귀 |
| `Intensity Scale` | **3.5** | 카메라를 향한 면을 밝힐 수 있는 유일한 레이어 |
| `Lower Hemisphere Is Black` | **해제** | 안 풀면 아래 색이 무시됨 |
| `Lower Hemisphere Color` | `#2A2038` | |
| `Min Occlusion` | **0.2** | AO 바닥값. 구석이 완전히 죽지 않게 |
| `Occlusion Tint` | `#1A1428` | ↓ |

**`Occlusion Tint` 가 오늘의 발견이다.**
기본값이 검정이라 모서리 음영이 회색으로 죽는데, 어두운 보라를 넣으면 접지 음영이 **쿨톤**으로 깔린다.
*"그림자는 검정이 아니라 보색"* 이라는 원칙을 **별도 라이트 없이 공짜로** 얻는 방법.

## Layer 3 · PostProcess — 해석한다

### 담당

**앞의 두 레이어가 만든 빛을 어떻게 읽을 것인가.**
카메라 설정에 가깝다. 필름을 바꾸는 것이지 조명을 바꾸는 게 아니다.

### 못 하는 것

**없는 빛을 만들지 못한다.**
Layer 1·2 가 비어 있는데 여기를 만지면, 정보가 없는 픽셀을 늘리는 것이라 **뿌옇게 뜨기만 한다.**

### PP 안에서도 레이어가 나뉜다

여기가 오늘 가장 크게 배운 부분이다. PP 항목들은 **각자 다른 값 대역에 작용한다.**

```
값 대역:   어두움 ──────────── 중간 ──────────── 밝음
              │                  │                 │
Exposure    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  전부
Shadows Gain ━━━━━━━━                                어두운 쪽만
Global Gamma          ━━━━━━━━━━━━                   중간톤
Bloom                                    ━━━━━━━━━━  밝은 쪽만
AO          ━━━━━                                    접촉부만
```

**"어둡다" 는 증상에 `Exposure` 를 올리면 안 되는 이유가 이 그림에 다 있다.**
전 대역에 작용하므로 하늘까지 같이 떠서, 애써 만든 대비가 통째로 날아간다.
어두운 부분만 올리고 싶으면 그 대역에 작용하는 도구를 써야 한다 — `Shadows → Gain`.

### 오늘의 사건 1 — 모닥불이 흰색으로 탔다

주황 불빛인데 화면에서는 순백이었다.
**밝기가 과해서 RGB 가 전부 1.0 을 넘어가면 색 정보가 사라진다.** 라이트 색의 문제가 아니라 노출의 문제였다.

→ `Metering Mode: Manual` + `Exposure Compensation` 을 내리며 **불빛 중심이 흰색이 아니라 주황으로 보이기 시작하는 지점**을 찾음.

### 오늘의 사건 2 — 빈 씬에서 잡은 노출은 무효였다

빈 씬에서 −1.5 가 맞았는데, 어두운 건물과 캐릭터가 들어오자 너무 어두워졌다. −0.6 으로 되돌렸다.
**아트가 들어올 때마다 라이팅을 재조정하는 건 실수가 아니라 정상 과정이다.**

### 값

| 항목 | 값 | 작용 대역 |
|---|---|---|
| `Infinite Extent (Unbound)` | ✅ | — |
| `Metering Mode` | **Manual** | 색을 고르기 전에 반드시 잠글 것 |
| `Apply Physical Camera Exposure` | 해제 | |
| `Exposure Compensation` | **−0.6** | 전 대역 |
| Color Grading → Shadows → `Gain` | **1.35** | 어두운 쪽만 |
| `Bloom Intensity` | **0.4** | 밝은 쪽만 |

> **Bloom 을 0 으로 죽이지 말 것.** 로우폴리라고 다 끄는 게 답이 아니다.
> 모닥불이 번져야 불처럼 보인다. 꺼야 하는 건 Lens Flare / Chromatic Aberration 쪽.

## 보너스 · PointLight (모닥불) — 국소 액센트

세 레이어 위에 얹는 **국소** 광원. 씬 전체가 아니라 반경 안쪽만 담당한다.

여기서 배운 것 하나: **Lumen 을 껐으므로 Niagara 이미시브는 주변을 밝히지 못한다.**
`NS_Fire` 파티클은 자기 자신만 밝게 그려질 뿐이라, 실제 라이트 컴포넌트가 반드시 별도로 필요하다.
Lumen 이 켜져 있었다면 이미시브가 간접광으로 퍼졌겠지만, 우리는 통제권을 얻는 대가로 그걸 포기했다.

| 역할 | 담당 |
|---|---|
| `NS_Fire` (Niagara) | 불꽃을 **그린다** |
| `FireLight` (PointLight) | 주변을 **비춘다** |

플리커는 코드로 넣었다 — [`ABGCampfire::UpdateFireFlicker`](../../Source/BG/Private/Core/BGCampfire.cpp).
**위치 흔들림이 밝기 흔들림보다 중요하다.** 밝기만 흔들면 씬 전체가 균일하게 명멸할 뿐이고,
둘러앉은 7명의 **그림자가 살아 움직이는 것은 광원이 실제로 움직일 때뿐**이다.

### 언리얼 함정 하나

**생성자에서는 `SetIntensity()` 류의 함수가 조용히 무시된다.**
이 함수들은 `AreDynamicDataChangesAllowed()` 를 확인하는데, 컴포넌트가 아직 등록되기 전이라 false 가 나온다.

```cpp
// 생성자 — 프로퍼티에 직접 대입
FireLight->CastShadows = true;
FireLight->SourceRadius = 15.f;

// OnConstruction / BeginPlay — Set 함수
FireLight->SetIntensity(FireIntensity);
```

## 레이어를 분리해서 검증하는 법

라이팅이 안 잡힐 때 **하나씩 꺼보면** 어느 레이어의 문제인지 바로 나온다.

| 검증 | 방법 | 통과 기준 |
|---|---|---|
| Layer 1 만 | SkyLight 를 `Affects World` 해제 | 형태가 읽히나 (면마다 명암이 갈리나) |
| Layer 2 만 | Directional 을 `Affects World` 해제 | 실루엣이 배경에서 분리되나 |
| Layer 1+2 | PPV 를 `Enabled` 해제 | 톤 보정 없이도 값 범위가 나오나 |
| 전체 | 뷰포트 **Lit → Lighting Only** | **회색이 3단계 이상 갈리나** |

마지막 항목이 가장 빠른 판정법이다. 머티리얼 색이 빠지고 빛만 남으므로 **라이팅이 형태를 만들고 있는지**만 순수하게 보인다. 균일한 회색 한 덩어리면 아직 Layer 1 이 일을 안 하고 있는 것이다.

## 증상 → 레이어 진단표

오늘 헤맨 것들을 표로 정리했다. 다음에는 이걸 먼저 본다.

| 증상 | 잘못된 대응 | 맞는 레이어 |
|---|---|---|
| 캐릭터가 검은 실루엣 | Exposure 올리기 | **Layer 2** — SkyLight Intensity |
| 화면이 전체적으로 어둡다 | Exposure 올리기 | **Layer 3** — Shadows Gain (어두운 쪽만) |
| 형태가 평평하다 | SkyLight 올리기 | **Layer 1** — Directional 각도·강도 |
| 그림자가 아예 없다 | Intensity 올리기 | **Layer 1** — Shadow Distance / Pitch 계산 |
| 불빛이 흰색으로 탄다 | 라이트 색 바꾸기 | **Layer 3** — 노출 (채도 손실) |
| 씬이 단색으로 뭉갠다 | 라이트 색 바꾸기 | **Layer 2** — 앰비언트 색 (하늘이 곧 앰비언트) |
| 모서리 음영이 회색으로 죽는다 | AO Intensity 올리기 | **Layer 2** — Occlusion Tint |

**패턴이 하나 보인다.** 오늘 잘못 대응한 것의 대부분이 `Exposure` 였다.
전 대역에 작용하는 도구라 뭘 해도 "일단 변하긴" 하는데, 그래서 더 위험하다.

## 그 아래 — 프로젝트 렌더링 설정

레이어를 쌓기 전에 바닥을 먼저 정했다. 로우폴리인데 프로젝트가 실사 프리셋이었다.

```ini
r.DynamicGlobalIlluminationMethod  1 → 0   Lumen off
r.ReflectionMethod                 1 → 2   Screen Space
r.Substrate                     True → False
r.Nanite.ProjectEnabled         True → False
r.AntiAliasingMethod               0 → 4   None → TSR
r.CustomDepth                      1 → 3   스텐실 포함
```

조용히 고장나 있던 두 줄:

- **`r.AntiAliasingMethod=0`** — AA 가 꺼져 있었다. `r.MSAACount=4` 가 적혀 있지만 디퍼드 셰이딩이라 MSAA 는 동작하지 않는다. 로우폴리는 깨끗한 실루엣 라인이 생명인데 그 라인이 계단으로 지글거리고 있었다.
- **`r.CustomDepth=1`** — `1` 은 뎁스만이고 스텐실을 쓰려면 `3` 이어야 한다. `BGTargetHighlight.cpp` 가 스텐실 값을 찍고 있는데 **읽을 버퍼가 존재하지 않았다.** 코드는 멀쩡한데 아웃라인이 원천적으로 안 나오는 상태.

**Lumen 을 끄는 것은 품질 하락이 아니라 통제권 확보다.**
스타일라이즈드의 목표는 물리적으로 정확한 빛이 아니라 의도한 빛이다. Lumen 이 켜져 있으면 간접광이 계속 색을 바꿔서 톤을 고정할 수 없다.

베이크도 하지 않기로 했다. 씬 반경이 10m 남짓, 라이트가 5개뿐이라 전부 Movable 로 둬도 성능이 남는다.
베이크를 끼우면 값 하나 만질 때마다 Build Lighting 을 돌려야 해서 **이터레이션 속도를 잃는다.** 색감 잡는 단계에서는 그게 가장 비싸다.

## 오늘 배운 것 요약

1. **레이어를 아래에서 위로 쌓는다.** Layer 1 이 비어 있는데 Layer 3 을 만지면 반드시 두 번 일한다.
2. **각 레이어는 대체 불가능하다.** PP 로 라이팅을 만들 수 없고, SkyLight 로 형태를 만들 수 없다.
3. **PP 안에서도 값 대역이 나뉜다.** "어둡다" 에 Exposure 를 쓰면 대비가 날아간다.
4. **그림자 길이 = 높이 / tan(고도).** 태양 각도와 그림자 거리는 반드시 같이 정한다.
5. **값을 만지기 전에 구조를 본다.** 캐릭터가 어두운 이유는 좌석 배치 코드에 이미 적혀 있었다.
6. **"값을 넣었는데 안 나온다"** 는 (a) 무시 (b) 곱셈 (c) 덮어쓰기 순서로 의심한다. 오늘은 `Overall Color` 가 하늘 전체에 곱해지고 있었다.
7. **단계마다 같은 앵글로 스크린샷을 남긴다.** 눈이 금방 적응해서 "나아지고 있는지" 감각이 마비된다. 비교 컷이 유일한 방어책이다.
